## Labeling conventions

- Functions without a symbol name keep the generated `sub_<addr>` /
  `FUN_<addr>` name in both `cachebeta.elf.c` and `cachebeta.elf.asm` — the label in the
  `.asm` is the anchor for the same function in the `.c`.
- Unnamed data referenced by the C appears as `dat_<hex>` (the hex is the VMA);
  the same spelling labels the bytes in the `.asm` data tail. When a named
  global covers that address the symbol name stays the label and the `dat_`
  spelling is appended: `<name>:  ; 0x<addr> = dat_<hex>`.
